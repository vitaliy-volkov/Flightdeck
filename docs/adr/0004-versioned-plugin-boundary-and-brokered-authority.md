# ADR 0004: Версионированная граница плагинов и брокер полномочий

## Контекст

Плагины расширяют Flightdeck недоверенным исполняемым кодом, могут запрашивать доступ к shell, файлам, сети, памяти и внешним сервисам и должны обновляться независимо от ядра. При этом расширение не может обходить ворота процесса, менять исходный brief или превращать автоматический режим в неограниченное разрешение на внешние и необратимые действия.

## Решение

Сделать plugin API отдельным версионированным протоколом с manifest, `api_version`, совместимостью агентов, объявленными capabilities и lock-файлом источника. Запускать entrypoint отдельным процессом по строгому JSON Lines контракту. Все полномочия выдавать по модели default deny через ядро-брокер; capability разрешает только заявленный класс операции, а внешняя запись, публикация, удаление, платёж и переписывание истории всегда требуют отдельного runtime approval event. Несовместимый или некорректный плагин отключается локально, не выводя из строя ядро и не пропуская gate.

## Почему

Единая граница связывает совместимость, изоляцию отказов и контроль полномочий: версия определяет допустимый контракт, manifest — запрашиваемые права, а брокер — фактически разрешённое действие. Отвергнуты плагины внутри процесса, потому что сбой или побочный эффект смешивается с ядром; allow-by-default, потому что установка не равна согласию на полномочия; прямой доступ плагина к внешним системам, потому что он обходит аудит и approval; версионирование только вместе с ядром, потому что оно связывает независимые циклы выпуска; продолжение после несовместимости «на удачу», потому что оно делает результат недоказуемым.

## Последствия

Плагины можно устанавливать и обновлять независимо, их отказы локализованы, а чувствительные эффекты остаются наблюдаемыми и подтверждаемыми. Tradeoffs — отдельный процесс не является полноценной OS sandbox, брокер и строгая схема усложняют authoring, а новые возможности требуют эволюции API и политики совместимости. Отмена решения потребует перестройки протокола hooks, install/lock, модели approvals, аудита и всех интеграционных контрактов.
