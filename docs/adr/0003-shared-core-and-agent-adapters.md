# ADR 0003: Общее ядро и тонкие адаптеры агентов

## Контекст

Flightdeck должен давать одинаковую семантику фаз, требований, режимов и ворот в Codex, Claude Code и Cursor, хотя доступные действия и способы их вызова различаются. Недоступная возможность не должна изображаться как успешно выполненная.

## Решение

Сосредоточить бизнес-правила, переходы и инварианты в общем декларативном ядре. Для каждой агентской среды использовать тонкий профиль-адаптер, который обнаруживает возможности и отображает общий action в конкретный invocation, evidence или явный blocker. Неподдерживаемое действие возвращает безопасную деградацию либо блокировку и не меняет состояние на «выполнено».

## Почему

Общее ядро делает поведение переносимым и позволяет проверять один сценарий контрактными тестами для всех агентов. Отвергнуты независимые реализации процесса для каждого агента, потому что они неизбежно расходятся в правилах и исправлениях; универсальный адаптер с неявным определением среды, потому что он скрывает различия возможностей; эмуляция отсутствующих действий, потому что она создаёт ложные доказательства выполнения.

## Последствия

Добавление агента требует нового адаптера и прохождения общего контракта, но не копирования процесса. Tradeoff — общий набор actions ограничивает ядро пересечением выразимых операций, а agent-specific возможности требуют явных расширений или fallback. Изменение этого решения затронет модель переходов, профили агентов, доказательства выполнения и всю матрицу контрактных тестов.
