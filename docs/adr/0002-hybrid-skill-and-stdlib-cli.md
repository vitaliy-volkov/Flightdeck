# ADR 0002: Гибридный SKILL и CLI на Python stdlib

## Контекст

Flightdeck должен одновременно оставаться понятным AI-агенту процессом и детерминированно управлять состоянием, переходами, проверками, плагинами и восстановлением после прерывания. Он должен запускаться в разных агентских средах без обязательного Node.js и без установки сторонних Python-пакетов.

## Решение

Разделить продукт на человекочитаемый `SKILL.md` с прогрессивно раскрываемыми инструкциями и исполняемый CLI на Python 3.11+, использующий только стандартную библиотеку. Skill описывает намерение и порядок взаимодействия агента с процессом; CLI является авторитетным механизмом для версионированного состояния, валидации, команд жизненного цикла, плагинов и экспорта.

## Почему

Такое разделение сохраняет переносимость skill-формата, но выносит критические инварианты из вероятностного исполнения инструкций в тестируемый runtime. Stdlib снижает барьер установки и поверхность несовместимости. Отвергнуты чистый Markdown/SKILL без runtime, потому что он не обеспечивает надёжные атомарные переходы и машинные проверки; обязательный Node.js или Python-фреймворк, потому что добавляет менеджер пакетов и зависимости; самостоятельное GUI-приложение, потому что оно не является необходимым для ядра v1.

## Последствия

Пользователь получает простой установочный контур и воспроизводимое поведение CLI, а агенты — читаемый контракт работы. Цена решения — поддержка двух согласованных представлений процесса и более ограниченный выбор библиотек; сложные возможности придётся реализовывать средствами stdlib либо сознательно откладывать. Изменение границы ответственности между skill и CLI потребует пересмотра форматов состояния, команд, тестов и документации.
