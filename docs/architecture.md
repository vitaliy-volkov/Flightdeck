# Architecture

Flightdeck separates a declarative workflow from agent-specific execution. `core` owns phases, modes, requirements, and gates; `state` owns versioned atomic JSON storage; `adapters` map common actions to Codex, Claude Code, or Cursor capabilities; `plugins` validate and dispatch isolated hooks; `cli` owns commands and exit codes; `reporting` renders redacted evidence.

State lives at `.flightdeck/state.json`. The original brief is immutable, later additions are append-only, and stable requirement IDs trace specification, work item, verification, and acceptance. Each transition requires validator evidence. A capability probe may choose a declared fallback; it may not simulate success.

The public CLI deliberately has no generic event injection command and does not accept user-approval JSON. User authority enters through a trusted adapter or embedding harness calling `next_actions(state, event, trusted=True)`; untrusted callers cannot grant approval or remove requirements. Outward action spellings are normalized before the single-use approval gate. Direct plugin powers remain default-deny, and plugin dispatch through the CLI cannot manufacture an approval.

`request_action` is a closed contract: only the six shared adapter actions are immediately eligible, while canonical outward actions require a trusted one-use approval. Every unknown action, including plausible aliases such as `send-email`, `charge-card`, and `remove-data`, fails closed.

Artifacts are stored beneath `.flightdeck/artifacts/`. An exclusive artifact lock serializes brief claims and concurrent additions; POSIX runtimes use a kernel advisory lock that is released automatically if a writer exits, with an atomic lock-file fallback elsewhere. The first `brief` write is final; subsequent user input uses the append-only `addition` kind. Versioned state records SHA-256 digests and source/phase provenance for the brief, combined additions, and acceptance. Every state load verifies those records and rejects direct modification, truncation, missing tracked files, or pre-seeded untracked acceptance. Blind acceptance cannot be recorded until the workflow reaches `acceptance` with review evidence present. `reporting.render(state, format)` is the single owner of canonical redacted JSON export and acceptance shape validation/rendering.

State schema v2 adds artifact integrity records. Loading a valid v1 state performs an in-memory migration and safely bootstraps digests from existing brief/additions. A v1 checkout containing any acceptance artifact fails closed because v1 has no trustworthy versioned provenance that can prove when it was created; phase names or neighboring review files are not treated as chronology. The artifact file and state file are two atomic writes rather than one filesystem transaction: interruption between them deliberately leaves a detectable mismatch, so subsequent loads fail closed. Stale lock recovery is an operational concern outside the v1 runtime contract.

The runtime is Python 3.11+ standard library. Optional agent capabilities affect execution strategy, not workflow meaning. See the skill's [phase contract](../skills/flightdeck/references/phases.md) and [mode contract](../skills/flightdeck/references/modes.md).
